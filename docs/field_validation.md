# 実機受入試験 — ソフトウェア回帰とRF実測を分ける

**この文書は試験手順・提案基準です。完了した実験結果ではありません。** CIでESP32向けbinが生成できても、実際の通信距離、C3/S3間の相互運用、技適、電源品質は検証されません。

## 固定・記録するもの

各ノードのボード型番/技適番号/アンテナ型番と版、ファーム環境とハッシュ、無線設定読み戻し、台数、役割、電源、筐体、アンテナの向き・高さ、設置距離、見通し/遮蔽物、周辺Wi-Fi、開始終了時刻を残します。LRを発射する前に対象構成・方式の認証条件を確認します。

無線readbackは `ready=true` / `readback_ok=true`、全ノード同じchannel/profileであることを確認します。LRは250kbps設定、BLE OFF、20MHz。通常は1000kbps設定、BLE OFF、20MHz。送信出力を未確認の値に引き上げません。RSSIは現行固定SDKでは未取得です。

## 1. 1ホップの比較

同じアンテナと配置で C3→C3、C3→S3、C3→C6、S3→C3、S3→S3、S3→C6、C6→C3、C6→S3、C6→C6 をそれぞれ双方向に実施します。まず近距離で正常性を確認し、距離を段階的に増やします。距離点は現地条件から決めます。64bytesと1000bytesを分け、各方向1000回以上、1秒以上の最小間隔、4秒以上の応答期限で測定します。

1000bytes試験は `ping_probe` のバイナリ試験です。`long_text` の32bytes単位の分割やSHA-256確認は使用しません。PCは `probe_bytes` を指定した `ping_probe` を送り、ファームウェアのバイナリ分割機構で送信します。遠端はプローブのFNV-1aハッシュを検証し、`probe_hash_ok` を含む `pong` を返します。成功条件は、期限内に宛先と `ping_id` が一致する `pong` を受信し、`probe_hash_ok == true` になることです。`probe_bytes`、PCで測定したRTTとp95、`request_hops`、`reply_hops`、RSSI、期限後Pong、重複Pongを記録してください。ファームウェアの内部フラグメントPDRや32bytes長文ACKを、この試験の成功条件にしないでください。

到達率は遠端Pongの照合結果を使います。未確定試行は分母に入れず、期限後Pong・重複Pongは別集計します。平均だけでなくp95、失敗区間、キュードロップ、再起動を記録します。条件を記録していない過去ログから距離を推定しません。

## 2. 中継の成立を実証

AとCが直接通信できず、B経由なら通信できる配置を作ります。単に3台を同じ机に並べる試験では多段中継を実証できません。送信電力の不正設定ではなく、配置・遮蔽・認められた測定設備で分離します。

`request_hops` / `reply_hops` が中継を示すことを確認します。このwire形式では直接受信の `hops=0`、中継1回が `hops=1`。経路表の `hops` はリンク数なので直接なら1で、表記が異なります。

A-C間で測定しながらBを停止すると通信が止まることを確認します。代替中継Dを含む菱形配置でも試し、primary断の検出、backup昇格、flood fallback、到達率の回復までの時間を記録します。MAC成功だけで遠端到達と判定しません。

## 3. 負荷・障害・再起動

3台→10台と段階的に増やし、複数の宛先指定送信、1KB試験、長文、キュー水位上昇を評価します。最低2時間、採用前には24時間以上の連続運用を提案します。ノード・PC・USBの切断/再接続、給電断、再起動、近傍入替、障害物や干渉の変化を個別に試験します。

故障時は失敗を隠さず、radio readback / `get_stats` / route_list / PCログを保存します。送信コールバックの停止を原因とする自動再起動が起きた場合、復帰しただけで合格にせず発生回数と原因を追います。

## 4. 提案する受入基準（未達成の目標）

短文の確定PDR 99%以上、1KBの確定PDR 95%以上、重複・破損データの誤成功0、停止要求後の勝手な再開0、無操作再起動0を初期基準として提案します。経路断からの回復時間は30秒以内を初期目安とし、用途と観測結果に応じて要求を確定します。距離だけ伸びても遅延・復旧・電源が要件未達なら採用しません。

## 5. macOS実機確認

Apple Silicon Macと実際のC3/S3をUSB接続し、列挙、接続、分割JSON受信、日本語送受信、2時間運転、USB抜き差し、終了後のポート解放、書き込み後のポート名変化を検証します。MacのCIでPythonテストが通ることと、USB実機検証は別です。Safari/Chromium双方で操作を確認します。

## 保存する成果物

アプリの「セッションを保存」でJSONを保存し、配置写真・距離点・測定者・全参加ノードのハッシュ/readbackを併記します。合成demoは実測レポートに混ぜません。PCログは直近2000件のリングなので、長時間試験では別のシリアル記録も使います。ログのtruncatedフラグを確認してください。
